# 07. 확장 포인트

## 목적
- 이 문서는 현재 전장 코어 규칙을 유지하면서 어떤 축으로 확장할 수 있는지 정리한다.
- 처음부터 모든 것을 확정하기보다, 무엇을 공통 기반으로 유지하고 무엇을 파생 규칙으로 뺄지 미리 나누는 것이 목적이다.

## 규칙
### 유지해야 하는 코어
- 지휘 유닛 중심의 이동 조작
- 전장 앵커 기반 위치 해석
- 웨이브형 스테이지 흐름
- 결과 판정과 AI 선택의 분리
- 모바일/PC 공통 이동 규칙

### 스테이지 타입 확장
- 기본 소탕형 외에 다음 타입을 파생시킬 수 있다.
  - 거점 방어형
  - 호위형
  - 탈출형
  - 제한 시간 생존형
- 스테이지 타입이 달라져도 `현재 어떤 목표를 지키면 되는지`를 HUD 한 줄로 설명할 수 있어야 한다.

### 전장 구조 확장
- 현재 기본형은 단일 로컬 전장이지만, 이후에는 `양방향 진입`, `복수 라인`, `보스 원형 경기장`으로 확장할 수 있다.
- 다만 라인이 늘어나면 이동 판단보다 시야 분산 문제가 먼저 커지므로, 전장 수를 늘리기 전에 UI 경고 체계를 먼저 강화해야 한다.

### 조작 확장
- 돌진, 회피, 순간 정지, 스킬 조준 모드 같은 능동 조작을 추가할 수 있다.
- 이때도 이동 조작의 의미를 지우지 않도록 `항상 켜진 기본 조작은 이동`, `짧은 순간만 개입하는 조작은 부가 기능`으로 나눈다.

### AI 확장
- 적은 단순 추적형에서 시작하되, 이후에는 우회형, 포위형, 지형 활용형, 역할 우선형으로 확장할 수 있다.
- 아군 자동 전투도 필요해지면 개별 캐릭터 AI보다 `지휘 유닛을 따라오며 거리만 맞추는 간단한 보조 규칙`부터 도입하는 편이 안전하다.

### 데이터 확장
- 맵 정보, 웨이브, 스폰 그룹, 스탯 보정은 계속 분리된 데이터로 유지한다.
- 이유는 같은 웨이브 구성을 다른 맵에 꽂거나, 같은 맵에서 난이도만 바꾸는 작업을 쉽게 만들기 위해서다.
- 새로운 규칙이 생기면 기존 데이터 파일을 비대하게 키우기보다, 파생 규칙용 데이터 조각을 별도로 나누는 편이 좋다.

## 예시 시나리오
- 현재 기본형 스테이지가 안정화되면, 같은 전투 코어를 유지한 채 `3분 버티기` 이벤트를 만들 수 있다.
- 이 경우 승리 조건만 `최종 웨이브 제거`에서 `제한 시간 생존`으로 바꾸고, 웨이브는 계속 압박을 주는 방향으로 설계하면 된다.

## 확장 포인트
- 다음 상세 문서 후보는 `보스 패턴`, `거점 방어 규칙`, `수동 스킬 개입 설계`, `맵 기믹과 이동 상호작용`이다.
- 세부 기획이 진행되면 이 문서는 `무엇을 공통 기반에 남기고 무엇을 파생 문서로 분리할지`를 판단하는 기준 문서로 유지한다.
