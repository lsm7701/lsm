# 08. AI 구현 현황

## 목적
- 이 문서는 현재 `RTS_Game/grow_game` 구현이 실제로 어떤 축으로 동작하는지 요약해, 여러 AI가 같은 전제를 공유하도록 만드는 구현 기준 문서다.
- 기획 방향 설명이 아니라 `지금 이미 있는 것`, `지금 없는 것`, `바꾸려면 어디를 봐야 하는지`를 빠르게 파악하게 하는 것이 목적이다.

## 규칙
### 현재 구현의 큰 구조
- 현재 신규 모드 축은 메인 브렌치 `G:\ccgMain` 안의 `grow_game` 계열 코드와 리소스를 중심으로 존재한다.
- 구현의 핵심 축은 `맵 로드`, `웨이브/스폰`, `직접 이동 입력`, `거리 기반 AI 반응`, `결과 확정 분리`다.
- 즉, 현재 기반은 `자유 전장형 실시간 전투 + 데이터 기반 웨이브 관리`에 가깝고, 완전한 신작 초안 상태는 아니다.

### 현재 소스 기준 경로
- 런타임 전장 핵심: `G:\ccgMain\Assets\Scripts\Battle\Simulator\Field\GrowGameField_New.cs`
- 적 AI 핵심: `G:\ccgMain\Assets\Scripts\Battle\Simulator\Field\AI\FieldAiSelectSkillGrowGame.cs`
- 전투 진행 Step: `G:\ccgMain\Assets\Scripts\Battle\Main\Step\GrowGame\GrowGameStepIng_New.cs`
- 메인 필드 프레젠테이션: `G:\ccgMain\Assets\Scripts\Battle\Main\Field\MainGrowGameField_New.cs`
- 이동 UI: `G:\ccgMain\Assets\Scripts\Battle\Main\UI\Vpad\WidgetGrowGameBattleVpad.cs`
- VPad 입력 로직: `G:\ccgMain\Assets\Scripts\Battle\Main\UI\Vpad\RTS_BattleUnitVpad.cs`
- 위치/타겟 helper: `G:\ccgMain\Assets\Scripts\Battle\Simulator\Skill\Common\GrowGamePlacementHelper.cs`, `G:\ccgMain\Assets\Scripts\Battle\Simulator\Skill\Condition\Targeting\GrowGameTargetingHelper.cs`
- 전용 테이블 원본: `G:\Design\trunk_Table\simulatorTableNew`
- 전용 테이블 산출물: `G:\Design\trunk_Table\simulatorTableNew\output`
- 런타임 JSON 리소스: `G:\ccgMain\Assets\Scripts\Battle\Resources\SimulatorTable_New\json`

### 현재 구현에서 이미 확인된 것
- 맵 정보는 `MapInfo` 테이블을 읽어 폴더, 월드 인덱스, 청크, 높이 샘플 사용 여부를 결정한다.
- 스테이지는 `ContentId -> stageIndex`처럼 연결되어 웨이브 스폰 데이터를 읽는다.
- 웨이브는 `현재 웨이브 스폰 완료 + 생존 적 정리`가 돼야 다음 웨이브를 예약한다.
- 승패 판정은 AI가 직접 끝내지 않고, 웨이브 상태를 확인한 뒤 결과 behavior를 생성하는 구조다.
- 지휘 유닛 이동 입력은 모바일 VPad와 PC 축 입력을 같은 방향 값으로 합쳐 처리한다.
- 이동 목표가 막힌 지형이면 마지막 워커블 지점까지만 이동하는 보정이 이미 있다.
- 적 AI는 플레이어 정지/이동 상태에 따라 다른 거리 기준으로 접근 반응을 바꾸는 구조가 있다.

### 현재 구현에서 아직 느슨한 것
- 주요 수치가 일부 코드 상수에 묶여 있어 완전한 데이터 드리븐 구조는 아니다.
- AI 반응 거리, 입력 샘플링 간격, 타겟 최대 거리처럼 기획 조정 가능성이 높은 값이 아직 전용 테이블로 분리되지 않았다.
- UI 경고, 웨이브 예고, 실패 보호 규칙은 전투 코어보다 문서화와 데이터화가 덜 된 상태다.
- 따라서 앞으로의 작업은 `없는 기능을 처음 만드는 것`보다 `이미 있는 기능을 어디까지 테이블/명세로 빼낼지`가 더 중요하다.

### AI 위임 시 반드시 같이 전달할 전제
- 이 모드는 완전 백지 상태가 아니라 `기반 구현 위 변경` 작업이다.
- 따라서 AI는 먼저 현재 구현 책임을 유지해야 하며, 역할이 다른 시스템까지 넓게 리팩터링하지 않는 것을 기본 원칙으로 한다.
- `문서의 목표 상태`와 `현재 코드의 책임 범위`가 충돌하면, 먼저 문서를 업데이트해 충돌 원인을 남긴 뒤 수정 방향을 좁혀야 한다.

## 예시 시나리오
- 웨이브 간 간격을 바꾸고 싶다면 먼저 `GrowGameField_New`의 예약 흐름을 보고, 그 값이 테이블화할 대상인지 코드 상수 유지 대상인지 구분한다.
- 적이 플레이어에게 너무 빨리 달라붙는 문제가 있으면 `FieldAiSelectSkillGrowGame`의 거리 반응 규칙과 관련 상수를 먼저 확인한다.
- 이동 조작감 문제가 있으면 `GrowGameStepIng_New`, `WidgetGrowGameBattleVpad`, `RTS_BattleUnitVpad`, `GrowGameField_New`의 입력 전달 흐름을 한 묶음으로 본다.

## 확장 포인트
- 이후 이 문서에는 `현재 구현`, `목표 변경`, `미구현 후보`를 버전별로 추가해 나가면 AI 작업 지시 정확도가 더 높아진다.
- 기능 단위 변경이 반복되면 마지막에 `작업 완료 상태 스냅샷` 섹션을 추가해 기준 문서로 고정하는 것이 좋다.
