# 10. AI 전용 테이블 명세

## 목적
- 이 문서는 `RTS_Game/grow_game` 전용 테이블이 현재 어떻게 엑셀로 관리되고, 어떤 산출물로 변환되며, 런타임에서 어디에 연결되는지 설명하는 AI 작업용 테이블 명세서다.
- 이후 테이블 추가가 필요할 때도 `어떤 책임을 새 테이블로 분리할지`를 같은 기준으로 판단하게 만드는 것이 목적이다.

## 규칙
### 현재 테이블 파이프라인
- 원본 엑셀 위치: `G:\Design\trunk_Table\simulatorTableNew`
- 산출 JSON/DB 위치: `G:\Design\trunk_Table\simulatorTableNew\output`
- 런타임 JSON 반영 위치: `G:\ccgMain\Assets\Scripts\Battle\Resources\SimulatorTable_New\json`
- 기본 원칙: 기획 수정은 원본 엑셀 기준으로 관리하고, 산출 JSON/DB는 변환 결과물로 취급한다.
- 작업 결과를 묶을 때는 엑셀 원본과 관련 산출물을 함께 보는 것을 기본으로 한다.
- `ExcelJson.log`는 작업 대상과 커밋 대상에서 제외한다.

### 1. GrowGame_MapInfo_New
- 원본 엑셀: `G:\Design\trunk_Table\simulatorTableNew\GrowGame_MapInfo_New.xlsm`
- 산출물: `GrowGame_MapInfo_New.json`, `growgame_mapinfo_new.db`
- 런타임 용도: 스테이지 또는 맵 키에 따라 맵 폴더, 월드 인덱스, 기본 청크, 높이 샘플 사용 여부를 결정한다.
- 대표 컬럼:
  - `mapFolderId`
  - `worldIndexId`
  - `defaultChunkId`
  - `useCommonFallback`
  - `useHeight`
  - `spawnGroupId`
- 주 사용 코드: `MainGrowGameField_New`, `GrowGameField_New`
- 수정할 때 보는 포인트: 어떤 스테이지가 어떤 맵 리소스 세트를 읽는지, 청크 fallback이 필요한지

### 2. GrowGame_SpawnTable
- 원본 엑셀: `G:\Design\trunk_Table\simulatorTableNew\GrowGame_SpawnTable.xlsm`
- 산출물: `GrowGame_SpawnTable.json`, `growgame_spawntable.db`
- 런타임 용도: 스테이지별 웨이브 순서, 그룹 연결, 시작 지연, 기본 성장 보정값을 정의한다.
- 대표 컬럼:
  - `stageIndex`
  - `waveIndex`
  - `spawnGroupIndex`
  - `baseUnitLevel`
  - `baseSlotGrade`
  - `groupOffsetPosX`
  - `groupOffsetPosY`
  - `waveStartDelaySec`
  - `enable`
- 주 사용 코드: `GrowGameField_New.LoadStageSpawnData`
- 수정할 때 보는 포인트: 웨이브 수, 등장 시점, 방향 압박, 난이도 상승 축

### 3. GrowGame_SpawnGroup
- 원본 엑셀: `G:\Design\trunk_Table\simulatorTableNew\GrowGame_SpawnGroup.xlsm`
- 산출물: `GrowGame_SpawnGroup.json`, `growgame_spawngroup.db`
- 런타임 용도: 하나의 스폰 그룹 안에 어떤 유닛을 어떤 순서와 로컬 좌표로 배치할지 정의한다.
- 대표 컬럼:
  - `spawnGroupIndex`
  - `unitOrder`
  - `unitId`
  - `addUnitLevel`
  - `addSlotGrade`
  - `localPosX`

- 수정할 때 보는 포인트: 유닛 편성 패턴, 전열/후열 느낌, 좌표 밀도, 추가 스킬 부여 여부

### 4. GrowGame_StatList
- 원본 엑셀: `G:\Design\trunk_Table\simulatorTableNew\GrowGame_StatList.xlsm`
- 산출물: `GrowGame_StatList.json`, `growgame_statlist.db`
- 런타임 용도: GrowGame 전용 스탯 프리셋 또는 초기 전투 수치를 정의한다.
- 대표 컬럼:
  - `statName`
  - `active1`
  - `active2`
  - `passive`
  - `ultimate`
  - `health`
  - `attack`
  - `defense`

- 주 사용 코드: 전투 시뮬레이터 계열의 스탯 로드 경로
- 수정할 때 보는 포인트: 적 체력만 올릴지, 공속/에너지/저항처럼 체감 축을 바꿀지

### 현재 테이블과 코드의 연결 방식
- 맵 정보는 필드 초기화 시점에 읽힌다.
- 웨이브와 스폰 그룹은 스테이지 진입 시 `stageIndex` 기준으로 한 번 로드한 뒤, 전투 중 상태머신이 순서대로 소비한다.
- 스탯 테이블은 유닛 성능과 직결되므로, 웨이브/스폰 변경과 함께 밸런스 축을 맞춰 봐야 한다.
- 즉, `맵`, `웨이브`, `그룹`, `스탯`은 서로 독립 파일이지만 실제 기획 변경은 보통 함께 움직인다.

### 추가 테이블 후보
- 아래는 아직 구현 확정이 아니라, 이후 AI 작업에서 테이블 분리가 필요할 때 우선 검토할 후보들이다.

### 후보 A. GrowGame_StageRule
- 추천 책임: 제한 시간, 첫 웨이브 지연, 다음 웨이브 대기 시간, 승패 타입, 타겟 최대 거리 같은 스테이지 공통 규칙
- 필요한 이유: 지금 일부 값이 코드 상수에 남아 있어 기획 반복 수정이 불편할 수 있다.

### 후보 B. GrowGame_AiRule
- 추천 책임: 정지 시 반응 거리, 이동 시 반응 거리, 거리 check 재적용 간격, 예외 적 타입 설정
- 필요한 이유: AI 반응 튜닝을 코드 수정 없이 반복하기 쉬워진다.

### 후보 C. GrowGame_UiRule
- 추천 책임: 웨이브 경고 노출 시간, VPad 표시 정책, 위험 경고 색상/아이콘, 실패 보호 UI 문구 키
- 필요한 이유: 전장 UX를 기획과 UI가 같이 조정할 때 코드 수정 범위를 줄일 수 있다.

### 후보 D. GrowGame_EventTrigger
- 추천 책임: 시간 기반 이벤트, 특정 적 처치 후 후속 스폰, 목표 오브젝트 활성화, 보스 페이즈 전환
- 필요한 이유: 단순 웨이브형을 넘어 조건부 전장을 만들 때 별도 데이터 축이 필요해진다.

### 후보 E. GrowGame_ResultRule
- 추천 책임: 클리어 조건, 실패 조건, 별점/랭크 평가, 보너스 조건
- 필요한 이유: 지금은 결과 판정이 주로 코드 구조에 묶여 있어, 콘텐츠 타입이 늘어나면 분리 필요성이 커질 수 있다.

### 테이블 변경 작업 체크리스트
- 먼저 변경 대상이 `기존 테이블 컬럼 조정`인지 `새 테이블 추가`인지 구분한다.
- 기존 테이블로 설명 가능한 규칙이면 새 테이블을 만들기보다 현재 구조 안에서 끝내는 쪽을 우선 검토한다.
- 새 테이블이 필요하면 `책임 한 문장`, `주 키`, `런타임 읽는 시점`, `연결될 클래스`를 먼저 문서에 적는다.
- 엑셀 수정 후에는 산출 JSON/DB와 런타임 리소스 반영 위치를 함께 확인한다.
- AI 작업 위임 시에는 어떤 테이블이 `진실 소스`인지 명시한다.

## 예시 시나리오
- 웨이브 간 대기 시간을 기획이 자주 바꿔야 한다면, 먼저 `GrowGame_SpawnTable` 컬럼 확장으로 해결 가능한지 검토한다.
- 적 반응 거리만 자주 조정되는 상황이라면, 스폰 테이블에 억지로 넣지 말고 `GrowGame_AiRule` 후보를 별도 테이블로 승격하는 편이 낫다.
- 맵별로 다른 경고 UI가 필요하면 `MapInfo`에 무리해서 넣기보다 `UiRule` 계열 후보를 검토한다.

## 확장 포인트
- 이후 실제 엑셀 시트 구조, 변환 매크로 규칙, 검증 순서까지 정리하면 이 문서는 `AI용 데이터 반영 가이드`로 더 강해질 수 있다.
- 새로운 전용 테이블이 생길 때마다 이 문서에 `원본 경로`, `산출 경로`, `대표 컬럼`, `연결 클래스`를 같은 형식으로 누적하는 것을 권장한다.
