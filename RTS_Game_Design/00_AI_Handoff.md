# 00. AI Handoff

## 목적
- 이 문서는 `RTS_Game/grow_game` 관련 문서를 여러 AI에게 그대로 전달할 때, 문서 우선순위와 작업 범위를 흔들리지 않게 잡아 주는 배포용 핸드오프 문서다.
- 문서 전체를 함께 넘기더라도 `무엇이 참고용이고 무엇이 이번 작업의 진실 소스인지`를 먼저 고정하는 것이 목적이다.

## 규칙
### 이 문서를 언제 쓰는가
- 여러 AI에게 같은 문서 세트를 배포할 때
- 문서 전체를 넘기되, 이번 작업 우선순위를 분명히 해야 할 때
- 코드 수정과 엑셀 테이블 수정이 함께 들어갈 수 있을 때
- 문서를 계속 갱신하면서, 추후 일괄 적용을 목표로 작업할 때

### 기본 전달 원칙
- 문서 전체를 전달하는 것은 허용한다.
- 다만 AI에게는 `전체 문서는 참고용`, `이번 작업의 필수 문서는 별도 지정`이라고 명시한다.
- 이번 작업과 무관한 리팩터링, 구조 청소, 네이밍 통일은 기본적으로 금지한다.
- 구현 변경이 문서와 충돌하면 먼저 문서를 갱신하거나 충돌 사항을 보고하고, 곧바로 넓은 범위 수정으로 들어가지 않는다.

### AI에게 반드시 같이 적어 줄 것
- 이번 작업 목표 한 문장
- 수정 범위
- 수정 금지 범위
- 완료 기준
- 검증 기준
- 엑셀 수정 포함 여부
- 문서 갱신 필요 여부

### AI 작업 결과 요청 형식
- 결과는 아래 형식을 기본으로 요청한다.
  - 변경한 파일 목록
  - 변경한 엑셀/JSON/DB 목록
  - 수정 이유 요약
  - 문서와 다른 점
  - 검증한 내용
  - 남은 리스크
- 이렇게 받아야 여러 AI 결과를 마지막에 비교하고 통합하기 쉽다.

### 문서 갱신 규칙
- 구현을 바꾸기 전에 문서가 충분히 명확하지 않으면 먼저 문서를 보강한다.
- 구현을 바꾼 뒤 문서와 달라진 부분이 생기면 최소한 `08`, `09`, `10` 중 해당 문서를 같이 갱신한다.
- 기획 방향이 바뀐 경우는 `01`부터 `07`까지를 갱신하고, 구현 반영 범위가 바뀐 경우는 `08`부터 `10`까지를 갱신한다.

### 테이블 작업 규칙
- `RTS_Game/grow_game` 전용 테이블의 진실 소스는 `G:\Design\trunk_Table\simulatorTableNew`의 원본 엑셀이다.
- 산출 JSON/DB는 변환 결과물로 본다.
- 테이블 작업이 포함되면 반드시 원본 엑셀, 산출물, 런타임 반영 위치를 함께 확인한다.
- `ExcelJson.log`는 작업 대상과 커밋 대상에서 제외한다.

### 병렬 위임 규칙
- 여러 AI에게 동시에 맡길 때는 쓰기 범위를 겹치지 않게 나눈다.
- 권장 분리:
  - A: 웨이브/맵/스폰/필드 규칙
  - B: AI 반응과 결과 판정
  - C: UI/VPad/입력 조작감
  - D: 테이블 구조와 데이터 반영
- 같은 파일을 두 AI가 동시에 수정하게 하지 않는 것을 기본 원칙으로 한다.

### 금지사항
- 이번 작업과 무관한 대규모 리팩터링 금지
- `grow_game` 기반 구조를 충분한 근거 없이 다른 모드 구조로 흡수하는 변경 금지
- 원본 엑셀 없이 산출물만 수정하고 끝내는 작업 금지
- 문서와 다른 전제를 임의로 만들어 기능을 확장하는 작업 금지
- 수정 결과를 문서에 전혀 반영하지 않는 작업 금지

## 예시 시나리오
- 사용자가 문서 전체를 Claude, Gemini, Codex 같은 여러 AI에 동시에 넘긴다.
- 각 AI에는 공통으로 이 문서를 먼저 붙이고, 담당 범위만 따로 써 준다.
- 한 AI는 웨이브와 스폰만, 다른 AI는 입력과 VPad만 보게 하면 결과 비교와 통합이 쉬워진다.
